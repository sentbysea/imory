Imory Core Components — Button v0.1

core/components/button.css 설계 미리보기입니다. 아직 실제 서비스 버튼 (.save-button, .logout-button, .back-button, .customize-icon-button 등)은 .imory-button으로 치환하지 않았습니다 — 이 페이지는 core/design-tokens.css + button.css만 불러와 독립적으로 렌더링됩니다.

  • 프로젝트 전체에서 버튼에 :active(눌림) 상태나 :focus-visible ring이 적용된 사례가 하나도 없었습니다 — 둘 다 이번에 새로 설계합니다.
  • #aaaaaa, #bbbbbb, #666666, #e5e5e5, #e8e8e8 등 버튼마다 조금씩 다른 회색 outlier가 있습니다. 이번 컴포넌트는 기존 semantic 토큰만 참조하고, 이 outlier들을 그대로 흡수하지 않습니다.
  • danger는 실제 .customize-icon-button-danger와 동일하게 기본 상태를 중립(secondary와 같은 회색 계열)으로 두고, hover에서만 --imory-red-50/200/500로 전환합니다 — 평상시엔 다른 버튼과 구별되지 않다가 실제 삭제 행동에 가까워질 때만 경고 신호를 주는 실제 패턴을 그대로 보존한 것입니다.

02 State → Token 대응표

실제 색은 위 버튼에 마우스를 올려 확인하고, 아래 표는 각 state가 정확히 어떤 토큰을 참조하는지 텍스트로 확인하는 용도입니다.

공통 규칙: 모든 variant는 hover와 focus-visible이 같은 색을 공유하고(키보드 사용자도 마우스 사용자와 동일한 신호를 봄), active는 항상 hover보다 딱 한 단계만 더 진해집니다 — variant를 넘나드는 과장된 효과(그림자, 확대 등) 없이 border/text/배경 톤 이동만으로 표현합니다.

03 Before / After

왼쪽은 admin-settings.css의 실제 .save-button literal 값을 그대로 재현한 것, 오른쪽은 새 .imory-button--primary입니다. 이 페이지에서만 비교용으로 재현했고, 실제 .save-button selector는 아직 건드리지 않았습니다. default/hover는 색이 사실상 동일합니다(literal → token으로만 바뀜) — active/focus-visible이 이번에 새로 추가된 부분입니다.

04 다음 단계

  • primary 방향 최종 확정 — .save-button의 default(회색) → hover(핑크) 동작을 그대로 Core 기준 패턴으로 승격. "항상 핑크"가 아니라 상호작용 시에만 accent가 드러나는 조용한 버튼. active/focus-visible만 새로 추가.
  • secondary는 .google-login-button/.logout-button 패턴을, ghost는 .back-button/.quote-preset-load의 실제 색(#aaaaaa)을, danger는 .customize-icon-button-danger의 "평소엔 중립, hover에만 red" 패턴을 각각 보존 — 결과적으로 primary/secondary/danger가 default에서는 거의 같은 회색으로 보이고, hover에서만 각자의 역할(핑크/회색 유지/빨강)이 드러나는 것이 Imory 전체의 실제 패턴입니다.
  • 확정됐으니 다음 단계로 .save-button / .customize-save-button부터 .imory-button--primary로 1:1 치환 (완전히 동일한 패턴이라 가장 안전한 시작점).
  • 그다음 .logout-button/.google-login-button → secondary, .back-button/.quote-preset-load → ghost, .customize-icon-button-danger → danger 순으로 검토.
  • sm 크기(26px/4px 8px/9px)는 이번에 새로 정한 값입니다 — 기존 spacing scale(4/8/12/16/20/24)에 정확히 맞는 컴포넌트 높이 토큰이 없어 literal로 남겼습니다. 필요하면 v0.2에서 --imory-control-height-* 신설을 검토합니다.
